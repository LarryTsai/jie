# AI 團隊

2026-10-09 作者授權建立。此處放可重用的角色指引，不是六個常駐 Agent，也不改變 Canon 或正文凍結。

開工先讀根 [AGENTS](../AGENTS.md)、[ROADMAP](../ROADMAP.md)，再讀任務所在分區的 AGENTS。構思、重構與創作審查另讀[共用創作準則](修仙故事創作準則.md)，按實際任務讀自己的角色指引，不必每次全讀。

| 角色 | 責任 |
|---|---|
| [主編統籌](主編統籌.md) | 定任務、調度、取捨、整合，承擔整體好看與同步責任 |
| [修仙故事寫手](修仙故事寫手.md) | 每人獨立創造完整故事，不把仙感、情感或中段交出去補 |
| [世界與人物編劇](世界與人物編劇.md) | 讓修士、文明與同期事件不依賴主角存在 |
| [故事總架構師](故事總架構師.md) | 把作者構想、競稿、選定故事與歷史版本整合成連續完整的長篇大綱，規劃篇幅與各條成長線；交主編派修與審查（2026-10-09 作者新增） |
| [長線架構師](長線架構師.md) | 建立跨篇、跨年選擇與雙向回收，保住當下兌現 |
| [獨立讀者Reviewer](獨立讀者Reviewer.md) | 未參與構思的人實讀比較，判追讀欲望，可全退 |
| [Canon核對員](Canon核對員.md) | 查來源與效力，提供保住精彩的最小修正 |
| [審查員](審查員/README.md) | 七種審查角度（一般讀者、修仙愛好者、主角、強敵與配角、PM 結構、偵探與邏輯、Canon），每稿挑二到三位；2026-10-09 作者提議 |

大篇、核心弧與被作者否定後的重構，遵循[三寫手競爭規約](../設定/00_故事定位/02_工作規約/AI團隊競爭創作規約.md)。四槽時先主編加三寫手，完成後再開獨立 Reviewer；角色可分階段兼任，但參與構思者不能冒充獨立 Reviewer。世界與長線支援按問題使用，不增加每篇必經流程。

多個版本或整段故事要合成唯一連續大綱時，主編先請[故事總架構師](故事總架構師.md)出融合架構與缺口清單，再派寫手補強、安排獨立審查與回查；總架構師不寫正文、不兼任審查。

例如「重構第一次聖土」：統籌提供共同邊界，三寫手隔離提出完整故事；獨立讀者比較；按實際缺口安排世界、長線與 Canon 查核；統籌取捨整合，再驗收改後故事。不得先給共同完整劇情讓三人換皮，也不得直接拼起所有候選。

角色檔是派工指引，不會自行啟動 Agent。競稿、任務單與驗收記錄仍放 `待整理/`，此處只留現行指引。

審查結果與修正接續放同一故事的討論工作資料夾，依[保存與接續方式](審查員/README.md)由主編維護；實例：[第21–28篇未關閉工作](../待整理/競稿/第21至28篇/修正接續.md)。接續檔是派工與覆核入口，不是自動運行的Agent。

審查與修正依[主編閉環](主編統籌.md)同輪完成：取捨派修 → 實際改稿 → 獨立覆核 → 受影響前後篇回查 → 唯一版本與資料同步。修正接續供保存與認領，主編不能只交待辦便結案，常規修正不需作者再次觸發。

2026-10-10仙感交付修正：作者核心期待列入派工與選後覆核；硬限制須有現行來源，AI工作排期可重排。秘境／鍛器／突破／爭寶核心審查須包含修仙愛好者角度，可由獨立Reviewer兼任；合理但失去奇觀、野心與高潮的稿件不得僅憑Canon無錯通過。具體做法見共用準則及各角色新增段。
